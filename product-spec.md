## 1. Идея продукта

Единая цифровая платформа спортивного комплекса Петровского сельского поселения: мобильное приложение (iOS + Android) для жителей, спортсменов, тренеров и судей.

Продукт мотивирует к регулярным занятиям спортом и здоровому образу жизни через:

- персональный рейтинг активности (баллы за посещения, тренировки, участие в соревнованиях);
- простую запись на тренировки любого формата (индивидуальные, групповые, самостоятельные, аренда);
- живую среду сообщества: клубы, события, лента новостей, друзья;
- персональную цель с планом подготовки (ГТО / регулярность / своя) и «Историей целей»;
- умную адаптацию нагрузок на основе самочувствия (опросы после тренировок) и подготовку к сдаче норм ГТО.

**Ценность для пользователя:** «Записался — сходил — получил баллы и стал частью сообщества». Цикл повторяемый, с заметным прогрессом.

## 3. Сценарии и цели (JTBD)

1. **Записаться на тренировку** в пару тапов: главная → расписание → слот → подтверждение.
2. **Не пропустить тренировку**: уведомления о начале, изменениях, отменах; карточка ближайших записей на главной.
3. **Видеть свой прогресс**: рейтинг и баллы на главной (дашборд) и в личном кабинете — с расшифровкой, за что начислены.
4. **Поставить цель и достигнуть её**: цель из пресета (ГТО / регулярность / своя) → метрика прогресса + дедлайн → план подготовки → выгрузка тренировок в календарь → сдача норматива / знак. ГТО — один из пресетов цели, а не отдельный модуль.
5. **Тренироваться осознанно**: опрос после тренировки → в следующий раз план подстроится под самочувствие.
6. **Быть в сообществе**: клубы по интересам, события, лента, друзья, приглашения.
7. **Попасть в клуб / на тренажёр**: QR-сканер для входа.
8. **Спланировать неделю**: календарь тренировок и записей, конструктор произвольной тренировки.

## 4. Механики (системные правила)

### 4.1 Аутентификация
Вход/регистрация по коду (SMS или email). Сразу после — выбор роли. Роль «судья» включается позже по запросу, а не при регистрации.

### 4.2 Рейтинг и баллы

Два раздельных трека.

**1. Баллы — трек активности (ежедневная мотивация).**
- Начисляются за активности: посещения (статус «посетил» — база, §4.4), тренировки, аренду, участие в соревнованиях, сдачу нормативов ГТО.
- **Уровни** по балансу: Новичок (0) · Активный (1000) · Мастер (2500). Повышение уровня — тост «Новый уровень».
- **Серия** (streak): 3 / 7 / 30 дней подряд → +10 / +25 / +75.
- Журнал начислений со статусами «подтверждено / ожидает / отклонено / система»; детали — по тапу на дашборде, полная версия — в личном кабинете.
- Рейтинг из баллов: общий / по региону / по друзьям.

**Таблица начислений (канон):**

| Действие | Баллы | Подтверждение |
|---|---|---|
| Тренировка в зале / по плану цели | +40 | QR (§4.11) |
| Самостоятельная / домашняя | +20 | тренер, лимит 3 не подтверждённых/неделю |
| Аренда площадки | +30 | QR при старте |
| Участие в соревновании | +50 | судья, протокол |
| 1 / 2 / 3 место | +100 / +75 / +50 | судья, протокол |
| Сдача норматива ГТО | +50 | тест-день |
| Знак ГТО: бронза / серебро / золото | +150 / +300 / +500 | результат теста |
| Серия 3 / 7 / 30 дней | +10 / +25 / +75 | система |

**Точки прикрутки в прототипе (без механики начисления):** статичный тост «+N» на экранах успеха — отчёт по тренировке (+40), результат ГТО (+50 за норматив, +150/300/500 за знак), «Моя цель» (+N).

**Античит:** QR динамический (обновление раз в 3 мин); домашняя — подтверждение тренера, лимит 3 не подтверждённых в неделю; соревнования — судья по протоколу; подозрение в накрутке → списание −50 в журнале.

**2. Рейтинги по видам спорта — соревновательный трек.**
- Вид спорта = клуб/секция (§4.18 `club`); ГТО — один из видов.
- Очки за места 1–8: 100 / 85 / 75 / 65 / 55 / 45 / 35 / 25; участие — +10. Период — сезон.
- Лидерборд по виду: «моё место» + топ + результаты (места на событиях).
- Механика начисления в прототипе не реализуется — правила фиксируются здесь, экраны используют статику.

### 4.3 Запись на тренировки
Четыре формата, каждая со своим флоу:
| Формат | Фильтры | Шаги |
|---|---|---|
| Индивидуальная | тип тренировки, тренер | фильтр → карточка тренера со слотами → запись/отмена |
| Групповая / событие | тип, тренер, возрастная группа, сложность | фильтр → запись/отмена |
| Самостоятельная | — | (см. конструктор тренировок) |
| Аренда (корт/площадка/ролики/зал) | — | выбор слота → запись/отмена |

После завершения любой записи приходит опрос «как прошло» → в конструктор предлагаются упражнения с корректировкой интенсивности/сложности.

### 4.4 Календарь и статусы записей
- Календарь запланированных тренировок: тап по дате → карточка тренировки (инфо, информация о прибытии, состояние после тренировки, если заполнен опрос).
- Календарь записей: просмотр всех (строчный режим) со статусами **посетил / не прибыл**, добавление/изменение/отмена.
- **Правило статусов**: «посетил / не прибыл» — база для начисления баллов.
- **Подтверждение участия = отметка «посетил» (один шаг):** QR-скан (§4.11), подтверждение тренером/судьёй или «я» (§4.20) фиксирует участие и автоматически ставит статус «посетил» — это и есть основа начисления баллов (§4.2). Отдельной ручной отметки «посетил» нет.

### 4.5 Конструктор тренировок
- Формирование произвольной тренировки и добавление её в календарь.
- Для ГТО — отдельная заготовка упражнений под сдачу нормативов.
- Рекомендации на основе предыдущих опросов о самочувствии.
- Добавление / отмена / изменение.

### 4.6 Опрос после тренировки
- Триггеры: после индивидуальной, после групповой, после аренды площадки.
- Пара коротких вопросов о самочувствии.
- Влияет на рекомендации конструктора при следующем планировании.

### 4.7 Лента новостей
- Фильтр по тегам: события площадки / события друзей / события клубов.
- Из новости можно перейти к мероприятию и записаться → событие появляется в календаре.

### 4.8 Клубы и сообщества
- Сообщества по интересам на главной.
- Внутри: мероприятия и соревнования сообщества, кто из друзей состоит.
- Клуб: расписание (самостоятельные / групповые / индивидуальные / аренда), быстрая запись из карточки события, шеринг ссылки на тренировку.

### 4.9 Друзья
Список друзей и их активность, пригласить друга / поделиться событием, удалить друга.

### 4.10 Уведомления
Типы: о начале тренировки, о новой записи, об отмене, о большом событии (например соревнование с участием спортшколы). Уведомление можно удалить.

### 4.11 QR-доступ
Сканер с переключателем вкладок: **вход в клуб** / **сканирование кода на тренажёре**.

### 4.12 ГТО (из ТЗ)
- План подготовки к сдаче нормативов (индивидуальный график).
- Отслеживание прогресса выполнения нормативов.
- Онлайн-консультация тренера.
- **Решение (зафиксировано):** ГТО — **не слой календаря и не отдельный модуль**. ГТО — пресет цели (§4.19): план подготовки (шаблон §4.16) выгружается в календарь как обычные тренировки категории `training` (форматы-атрибуты, §4.18); сдача норматива — **событие-тест**; «Дневник ГТО» = экран цели пресета ГТО (ступень, нормативы, прогресс, знак).

### 4.13 Чат и консультации (из ТЗ)
- Чат спортивного сообщества: личные и групповые чаты (клубы, тренер), фото/видео/голос.
- Консультации тренера.
- В новом флоу эти модули не упоминаются — **открытый вопрос** (см. §8).

### 4.14 ГТО — фактическое состояние (по анализу экранов из другого проекта)

**Логически ГТО уже интегрировано, визуально — нет.**

- **Данные:** кнопка «Добавить тренировки в календарь» в плане подготовки реально закидывает 9 тренировок (3 недели × 3 дня) + тест-день в общий календарь (с тостом-подтверждением). ГТО-подготовка — это **не пятый тип события**, а обычные тренировки, появляющиеся в общем календаре.
- **Визуал и навигация разъехались:** экраны `gto.html`, `gto-plan.html`, `gto-test.html`, `gto-workout.html`, `gto-result.html` живут на своей дизайн-системе — свои токены `:root`, шрифт Oswald вместо Inter, синий `#1a86e0` вместо акцента `#3b7bff`/фиолетового градиента, не подключают общий CSS, который используют основные экраны. «Назад» в `gto.html` ведёт на старую главную.
- **Приоритет при сборке:** пересадить ГТО-экраны на ДС v2 (`assets/ds.css`) и поправить навигацию — иначе модуль будет ощущаться чужеродным.

**Три разных «финиша» тренировки:**

| Флоу | Что происходит после | Проблема |
|---|---|---|
| `training-active` → `training-report` | Обычная тренировка → полный отчёт | — |
| `gto-workout` → возврат в `gto-plan` | Тренировка по плану ГТО → **без отчёта** | Пользователь не получает фидбек (сколько сделал, сколько минут), хотя после обычной тренировки получает |
| `gto-test` → `gto-result` | Сдача норматива → фиксация результата теста | Открывается не из тренировки, а из календаря; «назад» ведёт в календарь |

Смысловое разделение удачное: **«потренироваться по плану ГТО» = обычная тренировка**, **«сдать норматив» = событие-тест со своим замером**, это не тренировка.

**Решение (зафиксировано):** единый отчёт. ГТО-тренировка по плану завершается экраном `training-report` с меткой «ГТО» в шапке — тот же движок отчёта, что у обычной тренировки. Тост-возврат в план не используется (закрыто, §8.8).

### 4.15 Тренеры — две отдельные фичи
Сейчас тренеры нигде не смоделированы, кроме заглушки: кнопка «Спросить тренера» показывает тост «откроется в полной версии». Ни карточки тренера, ни выбора слота, ни привязки тренера к клубному событию нет. В ТЗ роль «тренер» не документирована (раздел 1.4).

Две разные фичи, обе пустые:
1. **Тренер как автор события** — кто создаёт «тренировку с тренером», как выбираются слоты.
2. **Тренер как канал консультации** — чат/вопросы тренеру.

Каждую проектируем отдельно (см. §8, вопрос 10).

### 4.16 Шаблоны тренировок — единая модель
В текущих экранах шаблоны уже фактически есть, но не оформлены как сущность:
- `gto-plan.html` (норматив → группы мышц → сетка «упражнение × 7 дней × 3 недели») — шаблон программы, захардкоженный под ГТО.
- «Повторить» в журнале тренировок — разовый шаблон из фактически проведённой тренировки (ad hoc, из истории).

**Единая сущность «шаблон / план»** = { название, теги-цели (общая форма / ГТО-норматив X / произвольная), сетка упражнений по дням, флаг «сгенерировать N тренировок в календарь» }.

Тогда: конструктор — редактор одного шаблона; ГТО-план — шаблон с прошитой целью-нормативом; «Повторить» из журнала — разовый шаблон из проведённой тренировки. Один движок вместо трёх параллельных (см. §8, вопрос 9).

**Решение (зафиксировано):** конструктор/план живёт в **профиле** (раздел «План тренировок»), а не в календаре. Результат — готовая сетка тренировок — **выгружается в общий календарь** по флагу «сгенерировать N тренировок» (та же механика, что в ГТО: «Добавить тренировки в календарь» = обычные тренировки в общем календаре, §4.14). В календаре никакого UI конструктора нет — только отображение выгруженных тренировок.

**План как часть цели (§4.19):** план входит в цель — «Цель = пресет + метрика прогресса + план (набор тренировок → набор упражнений) + дедлайн». ГТО-план = шаблон с целью-нормативом; «Повторить» из журнала = разовый шаблон из истории (тот же движок шаблона).

### 4.17 Меню управления событием (⋯)

Кнопка «⋯» (`.ev-card .ev-menu`) — в правом верхнем углу карточки события, на одной оси с пилюлей статуса (правый отступ `--space-4`). Тап открывает нижний лист действий `.sheet-list` (ЭТАП 9 ДС v2). Канон пункта меню: иконка-тайл 40 (`.sheet-ic`) · название (`.sheet-il`) · подсказка (`.sheet-ih`).

Канонический набор действий (эталон — ДС v2, «Меню „⋯“ · .sheet-list»):

| Действие | Иконка | Подсказка | Доступность |
|---|---|---|---|
| Напомнить | `ic-bell` | Уведомление за 30 минут | всегда |
| Поделиться с клубом | `ic-users` | Отправить участникам сообщества | события клуба |
| Перенести время | `ic-clock` | Доступно за 3 часа до начала | иначе пункт `.is-off` |

- Недоступное действие — `.is-off`: 45% прозрачности, без ховера; причина указана в подсказке (напр. «Доступно за 3 часа до начала»).
- Набор пунктов контекстный: для событий, которые создал я (`.is-org`, «Админ») — управление событием (перенос, отмена, редактирование); для записей на чужие события — управление записью (отмена, напоминание). Полная матрица ниже (канон — ДС §25 «Меню „⋯“», `design-system.html`).
- Отмена — `.sheet-cancel` под списком (канон листа, ЭТАП 9).
- Кнопка: в карточке события `.ev-card .ev-menu` — отдельные точки в правом верхнем углу (квадрат 24px, без обводки, ховер — фон `--surface-2` и смена цвета); в карточке цели (`.goal-top`) — круглая 32px с рамкой.

**Матрица «роль × статус события → пункты меню»** (эталон — ДС §25):

**Приглашение (pending)**
- Принять (is-ok) · Отклонить (is-danger) · Кто идёт · Поделиться

**Подтверждено (confirmed)**
- Отказаться (is-danger) · Кто идёт · Поделиться
- Дополнения по типу: + клубный чат (клуб), + сетка и календарь (ивент), + QR-код (аренда)

**Запись открыта (open)**
- Записаться (is-ok) · Кто идёт · Поделиться
- Дополнения по типу: + клубный чат (клуб), + добавить в календарь (ивент)

**Вы организатор (org) · по типам**
- Редактировать · Управлять участниками · Пригласить (is-ok) · QR-код входа · Изменить время · Клубный чат · Поделиться · Отменить / Удалить (is-danger)
- Тренер: «Подтвердить / Отклонить» (пока «Ожидает»), «Написать тренеру», «Отменить» после подтверждения.
- Ивент: «Посмотреть сетку», «Добавить в календарь».
- Индивидуальная: «Редактировать», «Изменить / Добавить тренера», «Отменить», «Удалить».

**Вы судья (роль на событии, §8.4)** — не статус события, а роль, как `org`; включается по запросу в карточке соревнования (§2)
- Внести протокол (is-ok) · Кто идёт · Поделиться
- «Внести протокол» — только **точка входа**; сам протокол — не пункт меню, а отдельный экран-ростер «участники → место» (баллы за 1/2/3 место, §4.2)

**Нет действий** — у завершённых / отменённых событий и при роли «нет связи» (none). Пункт «Все действия» детали карточки открывает тот же лист.

### 4.18 Типы и статусы событий — категории, форматы, статусы (канон — ДС §26)

Вся активность продукта делится на **4 сущности-категории**. Событие = **категория** (цвет + иконка + поведение) + **форматы** (чипы с ролью-цветом). Цвет дорожки карточки, иконка и свайп-действия берутся только из категории.

| Категория | Ключ | Токен · цвет | Кто заводит | Описание |
|---|---|---|---|---|
| Тренировка | `training` | `--type-training` #3ab5ad | пользователь или тренер | Занятие с форматами: личная, с тренером, групповая, онлайн |
| Ивент | `event` | `--type-event` #ff5a5a | администратор СП | Мероприятия самого СП: турнир, марафон, слёт, сбор; подтип задаёт админ (рабочее название прототипа) |
| Аренда | `rental` | `--type-rental` #3b7bff | пользователь | Бронь локаций клуба (поле, зал, корт и т.п.) |
| Клуб | `club` | `--type-club` #9175e8 | сообщество | Событие секции по виду спорта: сборы, выезды, тренировки клуба |

**Форматы — атрибуты, не отдельные типы.** «Личная», «с тренером», «групповая», «онлайн» — атрибуты одной категории «Тренировка». Итого 4 типа вместо 7+ — меньше цветов, сущностей и логики.

**Карта сущностей → категория + формат:**

- Личная тренировка → Тренировка + «Личная»
- Тренировка с тренером → Тренировка + «С тренером»
- Онлайн-тренировка / консультация → Тренировка + «Онлайн»
- Групповое занятие → Тренировка + «Групповая»
- Соревнование / марафон (событие по дате) → Ивент; челлендж — слой вовлечения, не событие (§4.20)
- Слёт / сбор поселения (заводит админ) → Ивент
- Аренда площадки → Аренда
- Тренировка клуба / сборы секции → Клуб
- Событие клуба → Клуб

**Легаси-ключи:** `me` и `trainer` из текущих экранов → категория `training` + формат-чип («личная» / «с тренером»). Алиас `--type-me` удалён: экраны используют `--type-training` напрямую.

**Статусы — 7 подписей** (статус отвечает на вопрос «что это для меня прямо сейчас?», на карточке всегда один):

| Статус | Ключ | Токен | Примечание |
|---|---|---|---|
| Приглашение | `pending` | `--st-pending` | любое событие, ждущее действия от меня; единственный требующий действия статус — жёлтый, пульс |
| Запись открыта | `open` | `--st-open` | можно записаться |
| Подтверждено | `confirmed` | `--st-confirmed` | я записался или принял (тренер, аренда) |
| Вы организатор | `org` | (роль, цвет жизненного цикла) | я создал/веду событие |
| Идёт | `ongoing` | `--st-ongoing` | событие началось (турнир на несколько дней, записи больше нет) |
| Завершено | `done` | `--st-done` | финальный |
| Отменено | `cancelled` | `--st-cancelled` | финальный |

Цвет — жизненный цикл (6 токенов: `--st-pending/open/confirmed/ongoing/done/cancelled`); «Вы организатор» — роль. Подпись карточки зависит от роли `org`: `pending → «Приглашение»`, `open/confirmed/ongoing/done/cancelled → «Вы организатор»`.

**Быстрые действия берутся из статуса** (согласовано с матрицей §4.17 / ДС §§24–25):

- **Приглашение** → «Принять · Отклонить» (тренеру — «Подтвердить»)
- **Запись открыта** → «Записаться»
- **Подтверждено** → «Отказаться · Кто идёт» (+ QR у аренды, + сетка у ивента)
- **Вы организатор** → «QR · Кто идёт · Редактировать · Перенести» (по типу)
- **Идёт** → «Результаты · QR» (по типу)
- **Завершено / Отменено** → без действий

### 4.19 Цели и «История целей»

**Модель цели (зафиксирована):** «Цель = пресет + метрика прогресса + план (набор тренировок → набор упражнений) + дедлайн».

- **Пресеты (альфа):** ГТО · Регулярность · Своя цель. («Разряд / Соревнования» — позже.)
  - **ГТО** — ступень + норматив (знак бронза/серебро/золото); метрика — нормативы/знак через тест-день (§4.12); план — сетка тренировок подготовки.
  - **Регулярность** — N занятий за период (напр. 12 занятий за месяц); метрика — занятия по плану; план — набор тренировок на период.
  - **Своя цель** — произвольная формулировка; без метрики прогресса; план необязателен.
- **Одна активная цель.** Создание новой цели завершает текущую; прошлые остаются в **«Истории целей»** (паттерн Strava / Samsung Health).
- **Смена цели не сбрасывает сырые данные** — журнал тренировок, нормативы и баллы остаются; «Сбросить прогресс» — деструктив только в настройках, не в целевом флоу.
- Экран «Моя цель» (`goal`, §6.4): шит пресетов → редактор метрики + дедлайна → карточка активной цели с прогрессом → «История целей». Точка прикрутки баллов — тост «+N» (§4.2).
- **Таб «Активности»** нижнего меню (бывш. «Тренировки», §4.20) → `activities.html` («Мои активности»): дашборд-герой со стриком и капом активной цели (ссылка в `goal.html`, читает `goal:active`), «План на сегодня» — те же `ev-card`, что «Ближ. События» на главной, «Неделя» — полоса Пн–Вс с числом активностей, «Журнал» — те же `ev-card` со статусом «Завершено» (`--st-done`) по неделям, тап — деталка (нижний лист `.sheet` с упражнениями из факта и «Повторить», §4.20), маркеры категорий (§4.18).
- **Карточка = категория × статус + всегда — ожидаемые баллы + связь с целью, если есть** (§4.20): на карточках «План на сегодня» под `.ev-place` — строка `.ev-pts` — ожидаемые баллы из таблицы начислений §4.2 (тренировка по плану цели +40, участие в соревновании +50, аренда +30) со звездой `ic-star`, и при связи с активной целью — маркер `.ep-goal` «шаг к цели» (`ic-target`, название из `goal:active`). Так карточка отвечает «зачем мне туда идти» — не только «что это».
- **Метрика прогресса цели (дельта 4):** `goal.html` пишет в `goal:active` счётную пару `metric: {label, done, total, next}` (ГТО — нормативы из «Прогресса нормативов», сдано/всего и следующий по `.is-next`; Регулярность — занятия по плану от целевого объёма N занятий × недели периода; Своя цель — без метрики). `activities.html` читает её: в капе «План на сегодня» — «Цель: … · 4/5», на карточках-шагах маркер `.ev-goal` — пилюля `ic-target` + «4/5» (формула «сделаешь — станет 5 из 5» — в `aria-label`). Число — счётный глагол: не «цель рядом», а «сколько осталось и что именно».

### 4.20 Слои и потоки — модель увязки механик

Все механики продукта — **5 слоёв** вокруг одного потока данных. Это не параллельные модули, а проекции одного факта: «я поучаствовал в событии».

| Слой | Вопрос | Что содержит |
|---|---|---|
| **Расписание** | «Что происходит» | События 4 категорий (§4.18), 7 статусов, запись/приглашение, QR |
| **Активности** | «Что я сделал» | Журнал подтверждённого участия (я / тренер / QR / судья), результат, «Повторить» |
| **Баллы и значки** | «Что я получил» | Начисление после события + опрос (§4.2), достижения по условиям |
| **Рейтинги и лента** | «Как я среди других» | Общий / по друзьям / по клубам; публикация результатов |
| **Челленджи и марафоны** | «Зачем продолжать» | Цели на период поверх активности; геймификация, а не события расписания |

**Один поток данных (спина):**

```
запись → подтверждение участия (QR / тренер / судья / я) → запись в Активностях → баллы + значок → рейтинг / лента → прогресс челленджа
```

**Правила увязки:**
- **Расписание пишет** события; **Активности хранят** факты участия; **баллы/значки** читают участия; **рейтинг/лента** читают результаты; **челленджи** читают активности за период.
- **Проверка механики:** на каком слое она живёт и что читает из потока? Если не пишет и не читает — её нет в потоке, значит она лишняя.
- **«Активности», а не «Тренировки»** — осознанный нейминг (§7): раздел хранит факты участия любой категории (включая клубные события и ивенты), и имя применимо к любой роли — **судья тоже фиксирует свою активность** (судейство), тренер — подтверждения участия.
- **День = набор фактов:** в один день может быть несколько активностей (тренировка + марафон + аренда). Журнал хранит их отдельными записями; «План на сегодня» — **список активностей дня** (при одной активности — карточка тренировки, §6.4); сетка «Неделя» в ячейке дня показывает **число активностей**; статы «Неделя» считают **активности (факты)**, часы — сумма длительностей всех фактов дня, серия — дни подряд с ≥1 фактом до сегодня. Экран `activities.html` построен этой моделью сверху вниз: **дашборд-герой со стриком** (плашка-огонь `ic-flame`, «дня подряд», статы часов/дней/активностей, кап активной цели — ссылка-строка с `ic-target` в `goal.html`, текст из `goal:active`) → **«План на сегодня»** — стопка **тех же `ev-card`, что «Ближ. События» на главной** (секция `.sec` с шапкой `.sec-head`, рядом ссылка «Расписание»): категория — цвет левого борта и статус-пилюли (`--c`, токены `--type-*`), формат — чип `.ev-fmt` без цвета; под `.ev-place` — строка `.ev-pts`: **ожидаемые баллы** из §4.2 (звезда `ic-star`; тренировка по плану цели +40, соревнование +50, аренда +30) и, если активность — шаг к активной цели, метка `.ep-goal` «шаг к цели: <название из `goal:active`>» (`ic-target`); тап по карточке — деталка (тренировка → воркаут, ивент → `evd-screen` с табами), «⋯» — контекстное меню → **«Неделя»** — полоса дней Пн–Вс с числом активностей в ячейке и сводкой «N из 7» → **«Журнал»** — группы по неделям («Эта неделя / Прошлая неделя / Ранее») с заголовком-сводкой «N записи · часы»; каждая запись — **тот же `ev-card`** со статусом **«Завершено»** (`--st-done`), категория — цвет борта, формат — `.ev-fmt`, результат — строка `.ev-place` (для ивента — результат протокола, напр. «3:42:11 · 124-е место из 487»); тап по карточке — **деталка** (для тренировки — нижний лист `.sheet` по канону ДС v2: шапка «название · когда · длительность», маркер «подтверждено: …» где есть, ось упражнений из факта `gpw:last.ex` — галочка `ic-check` на выполненные подходы, янтарь — частично, кнопка «Повторить»; для ивента — экран события с итогом), «⋯» — контекстное меню.
- **Роли (§2) в потоке:** спортсмен пишет и читает своё участие; тренер — создаёт события и подтверждает участие; судья — пишет результат (протокол), высшая форма подтверждения; администратор (веб-портал) — заводит ивенты и управляет статусами.
- **Смена статусов ивента — глобальное событие, не действие пользователя:** «Подтверждено → Идёт» запускает **администратор (веб-портал)** либо система сама в **момент старта** события. В прототипе — авто-флип по времени старта (демо: `?start=мс` в `15-event-marathon.html`); у пользователя нет кнопки «начать».
- **ГТО — вертикаль на том же потоке** (BR-10): подготовка = обычные тренировки `training` в календаре, сдача = тест-событие; добавляет свои статусы и баллы, но не новый слой.

**Единый реестр категорий:** категория события (§4.18) одна и та же в Расписании и в Активностях; в журнале дополнительно — маркер «как подтверждено» (я / тренер / QR / судья) и результат.

## 5. Пользовательские сценарии (ключевые флоу)

1. **Регистрация нового пользователя:** welcome → auth (код) → выбор роли → онбординг → анкета (ФИО, возраст, ID, сообщество, контакт родителя) → главная.
2. **Повторный вход:** welcome → auth → выбор роли → главная.
3. **Запись на индивидуальную тренировку:** главная → расписание → вкладка «индивидуальная» → фильтр (тип, тренер) → карточка тренера со слотами → запись/отмена → опрос после завершения.
4. **Запись на групповую тренировку:** главная → расписание → вкладка «групповая» → фильтр (тип, тренер, возрастная группа, сложность) → запись/отмена → опрос после завершения.
5. **Аренда площадки/корта:** главная → расписание → вкладка «аренда» → запись/отмена → опрос после завершения.
6. **Самостоятельная тренировка:** главная → календарь записей → все записи → конструктор → добавить в календарь.
7. **Просмотр рейтинга:** главная → дашборд активности → детали рейтинга.
8. **Управление друзьями:** главная → профиль → друзья → список / пригласить / удалить.
9. **Запись через новость:** главная → лента → фильтр по тегам → переход к событию → запись → событие в календаре.
10. **Быстрая запись из карточки клуба:** главная → ближайшие события клуба → расписание клуба → подтверждение записи.
11. **Сканирование QR:** главная → сканер → вход в клуб / тренажёр.
12. **Поставить цель ГТО:** главная → «Моя цель» → пресет «ГТО» → ступень + норматив → дедлайн → план подготовки → «Добавить тренировки в календарь» → тренировки по плану (обычные `training`) → тест-день → результат → знак + баллы.
13. **Мои активности:** таб «Активности» → дашборд-стрик → «План на сегодня» → журнал по неделям → «Повторить» (разовый шаблон) → активная тренировка → единый отчёт.

4. **Роль судьи:** судья — не глобальная роль пользователя, а **точечный доступ на конкретное событие** (§2, судейство включается по запросу в настройках карточки соревнования; §6.1 при регистрации не выбирается). В интерфейсе: роль-строка «Судья» в матрице §4.17 («Внести протокол» — только точка входа), сам протокол — отдельный экран-ростер «участники → место» (баллы за 1/2/3 место, §4.2). **Открыто:** одобрение запроса на судейство — ручное (веб-портал админа, там же где создаются ивенты) или самообслуживание? *(не блокирует сборку; точка входа судьи уже заложена, §8.4)*
5. **Правила начисления баллов:** **закрыт** — зафиксированы в §4.2 (таблица начислений, уровни, серии, античит; рейтинги по видам = клубы). Механика в прототипе не реализуется — только статичные тосты «+N» на экранах успеха.
6. **Существующие экраны из другого проекта:** полный перечень страниц для переноса и их маппинг на карту §6.
7. **Дневник посещаемости и награды/соревнования из ТЗ:** **закрыт** — дневник посещаемости (heatmap, §2.3.10) **реализован** в Профиле (раздел статистики, `rating-details.html`, вкладка «Посещаемость»): hero «N посещений», календарь-heatmap с уровнями, навигация по месяцам, график «По месяцам», «Экспорт»; модель — `GET /api/mobile/attendance` (тз.md:1025); награды = знаки ГТО (§4.2, карточка знака в профиле) + баллы и рейтинг; соревнования = события с сеткой/результатами (§4.17).
8. **Экран отчёта по всем типам тренировок:** **закрыт** — единый отчёт `training-report`; ГТО-подготовка — тот же движок с меткой «ГТО» в шапке (§4.14).
9. **Единая модель шаблонов/планов (§4.16):** **закрыт** — подтверждена: конструктор = редактор шаблона, ГТО-план = шаблон с целью-нормативом, «Повторить» = разовый шаблон из истории; план входит в цель (§4.19).
10. **Тренеры (§4.15):** две фичи (автор события + канал консультации), обе требуют дизайна с нуля; роль «тренер» зафиксировать в ролевой модели (§2). **Закрыт:** карточка тренера = подвид `profile-view` (аватары, роль «Тренер», клуб, консультации — «Написать»-тост, §8.3). Входы: автор события в деталке, строка тренера в детали клуба.
11. **Календарь и фильтрация:** файл `schedule-calendar.html` (логика фильтров/группировки) не был доступен для анализа — зафиксировать отдельно, как только появится.
12. **Меню управления событием (§4.17):** маппинг «роль / статус события → набор пунктов меню» зафиксирован (матрица в §4.17, канон — ДС §25). **Закрыт:** флоу действий для своих событий — через ⋯-меню (`.sheet-list`), «Перенести / Отменить / Редактировать» ведут в мастер `07-add-event` с предзаполненными данными (редактирование) или подтверждающий шит (перенос/отмена).
